# 人件費 会社負担の取り直し手順（フェーズB・鈴木さん承認後のみ実行）

対象: 業績ダッシュボードの payroll_data（DBの 2026-01 〜 2026-08 の8か月）。
変えるのは会社負担8項目だけ（健保・介護・厚年・子ども・子育て拠出金(支援金を合算)・厚生年金基金掛金・雇用・労災・一般拠出金）。
基本給・総支給・店舗・按分率（兼務）・月別調整は変えない。**DBの2026-09は暫定コピーのまま据え置く（スクリプトが拒否する）。**

## 方式（再取込ではなく「行IDで UPDATE」）
- 取込画面の再取込は deleteMany→createMany で行ごと作り直す。今回は店舗割当や按分率に触らないため、
  `scripts/payroll-recompute-company.ts` が会社負担8項目だけを行IDで UPDATE する。
- 月別調整（payroll_monthly_split）・マッピング（store_overrides / store_override_periods）は読みも書きもしない。
- 月 = DBのN月 ← クラウド給与の支給N+1月（`--offset 1`、既定）。

## 手順
1. **CSV を用意**（読み取り＝エクスポートのみ）: クラウド給与の支給控除一覧表 支給2月〜9月を
   `~/Backups/highalt-dashboard-payroll/<日時>/pay_YYYYMM.csv`（YYYYMM＝支給月・chmod 600）に置く。
   取得は `広告自動化/pl_mf_payroll_sync.py` の `fetch_payroll_csv` を使う。
2. **dry-run**（書き込まない・セッションが読み取り専用）:
   ```bash
   cd highalt-dashboard
   DATABASE_URL="<本番>" node --experimental-strip-types --no-warnings scripts/payroll-recompute-company.ts \
     --csv-dir ~/Backups/highalt-dashboard-payroll/<日時> --months 2026-01..2026-08
   ```
   「適用可（全月ブロックなし）」が出ること。BLOCK が出た月は適用しない（月のずれ・別人・重複を疑う）。
3. **バックアップ**（全表を \copy で CSV に。pg_dump はサーバー版との不一致で失敗しうるため使わない）:
   ```bash
   B=~/Backups/highalt-dashboard/$(date +%Y%m%d_%H%M%S); mkdir -p $B; chmod 700 $B
   for t in $(psql "$DB" -Atc "select tablename from pg_tables where schemaname='public' order by 1"); do
     psql "$DB" -c "\copy $t to '$B/$t.csv' csv header"
   done
   chmod 600 $B/*.csv; wc -l $B/payroll_data.csv
   ```
   ※ 接続は sslmode/pgbouncer のパラメータを外した URL を使う。バックアップ先はリポジトリの外（コミットしない）。
4. **適用**（1トランザクション。行数・基本給・総支給が変わっていないことを検算し、NGなら ROLLBACK）:
   ```bash
   DATABASE_URL="<本番>" node --experimental-strip-types --no-warnings scripts/payroll-recompute-company.ts \
     --csv-dir ~/Backups/highalt-dashboard-payroll/<日時> --months 2026-01..2026-08 \
     --apply --backup-dir $B
   ```
   `--backup-dir` の payroll_data.csv の行数が現在の表と違うと適用しない。
5. **検算**: dry-run をもう一度実行 → 全月「変わる 0行」（冪等）。ダッシュボードの法定福利費が dry-run の差額どおり増減していること。
   月別調整・マッピングの件数（payroll_monthly_split / store_override_periods / store_overrides）が適用前と同じこと。
6. **ロールバック**: 該当月の会社負担8項目をバックアップ CSV の値に戻す（行ID単位）。
   ```sql
   -- 一時表に payroll_data のバックアップを読み込み、id で会社負担8項目だけ戻す
   create temp table bk (like payroll_data);
   \copy bk from '$B/payroll_data.csv' csv header
   update payroll_data p set health_insurance_co=b.health_insurance_co, care_insurance_co=b.care_insurance_co,
     pension_co=b.pension_co, child_contribution_co=b.child_contribution_co, pension_fund_co=b.pension_fund_co,
     employment_insurance_co=b.employment_insurance_co, workers_comp_co=b.workers_comp_co,
     general_contribution_co=b.general_contribution_co
   from bk b where p.id=b.id and p.year=2026 and p.month between 1 and 8;
   ```

## 以後の自動取込
取込コード（見出しで列を引く）は 97列版・99列版のどちらも読める。未対応の「(会社)」列が増えたら止まる。
9月分（支給 10/31）は確定後の自動取込で入る。DBの9月は暫定コピーのままなので、自動取込は「取込済み」で止まる。
→ 9月を実データにするときは、9月の行を人が確認のうえ別途入れ替える（このスクリプトの対象外）。
